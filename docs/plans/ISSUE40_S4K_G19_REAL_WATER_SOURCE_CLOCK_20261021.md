## Safety issue in current architecture

The historical entry `g19_load_original_source_case(paths)` parses original source file records and immediately constructs a **physical-ready** selected G14/DIAGNO/COMP case. It correctly rejects the real 2SS 82×85 water-bearing `GEO.DAT` with `G18D3 all-land HFLUX default branch only`. However, that makes the source reader's refusal impossible to distinguish from the missing physical water state in G18D3, and incentivizes unsafe water category edits or weaker HEATFX controls. The already accepted native heat kernel `p6e::heatfx` does compute QSW on all cells but **preserves prior QH for water cells**: a separate original-equivalence audit must resolve actual QH provenance, model-hour carry state and ELUSTR/COMP water interactions before G14/G26 production is possible.

## Minimal, scoped engineering change (zero alteration to HEATFX physics)

- Introduce `G19SourceClockCase` owning exactly the previous READCF deck, immutable original GEO, ordered SS/US, SURF/UP and wind controls, plus the same fully validated all-hour source scheduler. No thermal/site physics or completed native outputs.
- `G19FileBackedCase` inherits the structural input case and **remains a distinct stronger type**, extending it with original STHEOR station-to-US assignments, SURFVAR and existing **unchanged G18D3 all-land HFLUX** admission. All existing `g19_load_original_source_case()` consumers, including selected 17-stage G14/G26, call this stronger constructor, not the new one.
- A separate `g19_load_source_clock_only()` returns **only** `G19SourceClockCase`. A C++ `static_assert(!std::is_convertible_v<G19SourceClockCase,G19FileBackedCase>)` makes accidental source-to-production promotion a compile-time error.
- The legacy preflight CLI retains its **unchanged default G19 physical** behavior (water reject). New explicit `--source-clock-only` mode checks real original met.inp/GEO/SURF/UP station IDs and full original 6h UTC bracket with independent scheduler, prints a distinct source-only sentinel and `G19_WATER_HEATFX=NOT_EVALUATED_OR_ACCEPTED`, no MET output.
- The scientific GitHub Action reexecutes exact genuine NOAA 2022 Huoshan 583140 + Luogang 583210 original observed 2SS, Anqing 58424 genuine IGRA 1US; regenerates real SRTM/GLCC P1–P5 inside SAME case and original MAKEGEO 6970×8 0-exceedance; then validates real 6h structural G19 source mode with original **water cells present**, old default mode still fails **specifically** at existing G18D3 all-land thermal guard, and missing-UP negative fails. The existing [#228](https://github.com/RRain001/CTEAS-next/pull/228) original 6h vendor CALMET reference also reruns in the cloned workflow to avoid source drift. Limited SHA/status artifact, no vendor source/raw NOAA/large MET output distribution.
