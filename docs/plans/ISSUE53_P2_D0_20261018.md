## 1. 结论与边界

现有 C++ P2 是 GEN 经纬度点 → USGS-92 类点数比例的选定路径；CLI 固定 Hefei 50×50@100 m、UTM50N 和三位小数原点。C++ 尚无本 Issue 要求的 GLCC 裸栅格原生直读，也无 GLC GeoTIFF 面积相交实现。Python GLCC 提取和 GLC 下载/资产验证层可复用作独立证据，但不等于原生计算已完成。

本 Issue 交付到 P2 fractions / LU.DAT，不实现 P3 的地表参数或 GEO.DAT；不调整 P1、P6/P7，也不新增分类产品和下载器。GLCC 点采样与 GLC 面积相交属于两个已经指定的计算口径，必须分别留证；二者年代、分辨率和分类体系不同，不互为数值 oracle。

P2 不读取排放率、释放时序或气象研究窗口。GLC 数据集的 `year=2022` 是来源时间元数据，不随气象年份自动替换文件。烟囱位置最多透传为案例元数据，不代替 `grid.cmn` 原点。

## 3. 原版同源依据与 GLCC 数值风险

本轮从兄弟仓库只读 `git show` 核查冻结旧提交 `dfad99a78ed84d655e21411c9d25eb0d2583bf13` 的 `engine/vendor/src/CTGPROC_v7.0.0_L150211/ctgproc.for`，实际SHA256为 `719abbd2327269bb0377208b3a7a0c74000b878efc756686023bbb2ef932f281`，与迁移 manifest 对应记录一致。没有复制/恢复/提交vendor源。

- 原版 `ctgproc.for:555–567`：`lumap` 和 `itab` 证实历史USGS-92类序及24→38表；`1889–1896` 是欧亚尺寸、1km格距、xorg=-8000、yorg=-5499、lat0=45、lon0=100。
- `2380–2500`：GLAZAS路径按源中心和 `MESHGLAZ` 细分；原始字节非法则计missing跳过；以`itab(lcc)`更新 LUGRID；0不是水，水是raw16→52。
- `3562–3582`：GEN路径把文本经纬度读入隐式 REAL*4，经过 `GLOBE(...dnzgen...)` 后调用 LUGRID。
- `4240–4290`附近：LUGRID用 REAL*4 差值/步长后赋整数，再对非负差值加1；有沿海分支，不能默认本Issue覆盖其全部开关。

**重要未决点：** Python注释称同mesh下GEN与GLAZAS逐格一致，尚不能据此推导新C++裸栅格路径的通用等价。GEN经过LAEA逆投影、7位经纬度文本、REAL*4再投影；原版GLAZAS直接以REAL*4 LAEA子点进入GLOBE，并有窗口/中心fuzz筛选。动态UTM边界可能放大区别。D1应分别进行“C++裸读 vs Python GEN”及“C++选定同源路径 vs 原版GLAZAS”的首次差异审计，并由 #42 确认选定权威链；不把GEN误差用容差放松掩盖。

## 5. 遵循已合并 B-0 的 P2 局部接口与 P2→P3 合同建议

建议由公共适配层解析既有case.yaml/grid.cmn，给P2只传所需规范化字段；不让P2重复决定公共配置。以下名字是建议，不是新配置系统。

```text
cteas_p2_fractions --grid GRID.CMN --profile REVIEWED_PROFILE
  --source-kind glcc-eurasia-raw|glc-fcs30d-geotiff
  --source FILE --expected-sha256 SHA --out-dir NEW_DIR
  [--mesh-cells 20] [--mapping REVIEWED_MAPPING]
```

- `GridSpec`：WGS84 UTM分区/半球、NX/NY正整数、DGRIDKM>0、**唯一且恰好三位小数** XREFKM/YREFKM文本；由grid.cmn承载已量化数值。建议用整米原点或文本→整米再换算，不能保留隐藏亚米double。旧`p2_gen_fraction`冻结检查原样保留；新profile必须显式获审。
- `SourceSpec`：kind、path、SHA、产品/版本/年份、CRS/transform、原始类命名空间；GLCC额外mesh和采样规则；GLC额外mask/NoData/合法35码及映射ID/SHA/批准状态。不能默认自动下载。
- 来源输出：`p2_manifest.json`，记录case/grid/source/config/code/toolchain SHA、CRS/轴序、方法、时间戳、许可、总/有效覆盖、门槛状态、首差异路径。GLCC与GLC不同run_id、不同状态。
- `p2_raw_fractions.csv`：`i,j,cell_area_m2,valid_area_m2,coverage_fraction,sample_count,raw_cat...`，单位明确；j南→北、i西→东，1-based，列序manifest显式列出；无对应统计填null而非伪0。GLCC点数比例不能标为真实面积，`valid_area_m2`/面积coverage为null，并另记missing与点覆盖。
- `p2_usgs92_fractions.csv`：同索引及冻结38类序；原始比例、mapped/unmapped fraction及合并来源可追溯；无有效覆盖/未审映射不得填全水/全零后归一。
- `LU.DAT` v2.1 兼容适配器归P2交付，但header字段与 #46共同审查；只在mapping获审且覆盖通过时生成。保留原版输出精度、类序、i最快行序与`.`行尾。高精度内部比例另存，不拿已舍入LU.DAT反推原始比例。新网格header必须含同一grid.cmn量化原点/尺寸/UTM，P3须独立核查。
- API建议：`compute_glcc_fractions(SourceSpec,GridSpec,SamplingSpec)` 与 `compute_glc_area_fractions(SourceSpec,GridSpec)` 两个明确分支，`apply_reviewed_crosswalk(...)`单独门禁。GLCC沿用counts；GLC用double m²，不滥用现有uint32计数结构。
