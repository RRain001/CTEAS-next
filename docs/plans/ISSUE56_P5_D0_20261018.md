2. `isd_to_smerge_and_fill.py:17-19`、`clean_merge_filled_by_research_time.py:12-16`、`convert_cleaned_to_smerge_ready.py:8-11`、`generate_smerge_input_sections.py:29` 在 import 时绑定全局路径。只给顶层新增 `--case` 不足以隔离全部输出。子进程 `run_fill` 还须保持明确工作目录（`:302-313`）。
3. `run_smerge_and_monitor.py:25-44,239-245` 在启动时再次读全局 current case；不能让显式 case 被覆盖。`:117-164` 发布数据和站表，`:307-310` 再做云量回填，应分别记录 raw native SURF 与 published SURF 哈希，原版对照比较同一处理层。
4. `clean_merge...:94-109` 取第一年头并 keep-last 去重；`generate_smerge_input_sections.py:309-317` 从实际站文件范围推断控制窗。新入口必须核对显式研究窗，不能让短数据自然缩短请求时间；跨年真实源/有效坐标变化不能静默采用第一年站表。
5. `engine/run_met/common.py:57-96` 直接把原点字符串转 float，不能替代严格三位小数词法校验；新入口需依 #42 批准的验证入口统一校验，不修改共享 parser 作为本 Issue 的附带动作。

## 3. 遵循已合并 B-0 的 P5 局部候选接口（不是已支持命令）

建议复用 `prepare_inputs`，新增显式 `--case-yaml <path> --work-dir <new-dir> --native-cpp-bin <path> --offline --raw-dir <archive> --history-file <path>`。默认离线；在线获取为显式操作并复用原下载层。是否将 grid/research 单独暴露给用户，由 #42 决定，避免两份可冲突权威。

API 建议：`run_p5(case_context, raw_archive, work_dir, native_bin, offline=True) -> P5Artifact`。参数名是设计建议；case_context 由 #42 的同一案例解析合同提供，本模块仅消费自身字段，不建立第二套 case schema。

| 消费字段 | 权威/单位 | 使用范围 |
|---|---|---|
| case ID、配置路径/哈希 | 既有 case.yaml | 运行绑定；相对路径基准必须统一 |
| grid 文件/哈希，IMAP/UTM区/半球/DATUM、NX/NY/DGRIDKM/XREFKM/YREFKM | grid.cmn；距离 km，原点字面与计算值严格三位小数 | 域内判定/站点有效位置；WGS84，复用现有算法 |
| stack lon/lat | 既有 puff.point_sources 与 #42 选定规则；度 | 域外最近源选择/虚拟位置；多烟囱选站位置的具体适配仍需协调 |
| UTC BEGIN/END | research_time 与 case.preprocess.research_time 一致 | 逐年选站和实际控制窗 |
| full/Lite 归档、history、输出路径 | 显式可读源与独立可写 scratch | 不写原始归档，不接触 project/current |

P5 不消费排放率/释放时序；它们由父合同保留给 P6/P7。

关键时钟事实：cleaner `:109` 裁剪 `[BEGIN,END]`，并在 `:150-165` 检查包含两端的主站风；C++ writer `:206-216` 输出 `(BEGIN,END]` 的完成小时记录，`:150-168` 把午夜终点写为前日24时。此处不是自动确认存在错误；已合并 B-0 明确 research_time 为包含两端的整时 UTC 标签。D1 必须证明 supporting rows、SMERGE 控制窗和 hour-ending labels 如何覆盖这些标签，保持既有原版语义；此映射仍是实现/审查事项，不能用改算法消除表面差一小时。

## 4. P5→#42 候选产物合同

保留现有原版兼容 `SURF.DAT`、`stations.csv`，按已合并 B-1 输出 `evidence/p5.json`（具体 JSON schema 待模块审查）。包含：case/grid/time/config hashes、生产者版本、受支持控制值、实际请求及输出 UTC 首尾/小时数、按 SURF 顺序的 IFSTN 与 NOAA full ID、源/有效坐标及 CRS、每年 primary/aux/virtual 角色和原始两源 coverage 分子/分母、逐时有效/缺失/静风及填补统计、归档/年度选择/GENERIC/control/raw-native/published-SURF 的 SHA。

使用现有 GENERIC 单位：温度°C、降水mm、压力mb、RH%、风向度、风速m/s、云量tenths、云高hundreds of feet（`test_p5_station_roles.py` 和现有 ready 头）；SURF 编码沿用写入器，不在旁车另造换算。

站点顺序必须来自实际控制和原生输出，不能从另一次排序推定。跨年 membership/坐标变动若不能由既有固定站头无歧义表达，应先 fail closed 并报告，后续在既有选项范围内设计分段交接；不能伪造常驻站或暗中扩大科学接受范围。G19 组装和 met.inp 索引核验归 #42。
