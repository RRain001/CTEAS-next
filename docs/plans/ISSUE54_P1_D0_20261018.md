## 1. 结论与科学边界

现有 #49 输入适配层已经支持本地多 TIFF 和 OpenTopography SRTMGL1 两条路线，应该直接复用。C++ 地形归格内核本身已有动态 NX/NY/格距参数，但 CRS 固定 UTM50N；CLI、P1→P3 序列化器和独立比较器仍固定合肥。因此不能只给 CLI 添加 NX/NY 就宣布完成通用化。

- `SAVEELEV` 2825 行，2928–2933 行调用 CELLIND/CELLDAT；`CELLIND` 6014 行，Cartesian 分支约 6085–6094 行执行 INT 再对非负坐标加一。

- 原版 10659 行对 `elev > 20000` 或 `< -10000` 置零；现 C++ 未实现这个分支。该事实不能用来授权新增自动置零。本次只沿用已选定算法；D1/D2 前须以实际 SRTM 值域和控制卡明确选定输入域，对超出已审查范围值 fail closed，或把该差异单列给负责人审查，不能暗改算法。

本次仅核查以上相关片段，不声称已完成 TERREL 全选项 callgraph、GET_IFD/COORDLIB 全源审查或数值等价验证。原版文件及 include/控制卡在后续同源比较时还须按 migration manifest 校验 SHA。

## 3. 必须解决的参数化缺口

1. **原点精度在 Python 层未闭合。** `engine/run_met/station_grid.py:14–22` 的 strict 只验证有限值/网格/CRS；底层 `engine/run_met/common.py:63–101` 将原点直接转 float，不检原始三位小数字面，重复字段后者覆盖、NX/zone 接受 `int(float(...))`。#49 source admission 不能独自保证三位小数契约。需要 #42 统一保留原点字符串并验证，不能事后打印 `:.3f` 代替计算约束。
2. **投影固定。** `terrain_grid.cpp:67` 使用 EPSG:32650。通用 spec 需含 zone、半球且只接受 WGS84 UTM；跨 zone 研究区仍用案例选定 zone，不能按每像元自动换 zone。
3. **CLI 和序列化固定。** 现 CLI 输出循环仍固定 50，P3 adapter 不读取 grid，通用结果不能送入旧 adapter。#54 负责地形结果，#46 负责动态 DAT/P3 适配，必须先冻结单一输出所有权。
4. **窗口/整图语义不同。** adapter 对单 TIFF 只检查 bbox 窗口 NoData，保留原文件；C++ 读整张并在任何 NoData 处拒绝（`terrain_grid.cpp:48–54`），也可能超出 staging 的窗口预算。`--allow-nodata` 只允许来源阶段留证，不能使 C++ 静默丢弃缺测。应先冻结同一选定 raster/window 语义；窗口必须对齐原栅格，不重采样，并验证裁剪前后 REAL*4 中心坐标序列不会漂移。现阶段保持拒绝，不能用放宽内核掩盖输入问题。
5. **source metadata 不等于 SRTM90m 产品证明。** local 当前写 `USER_PROVIDED_GEOTIFF`；无产品版本/垂直基准/许可字段，且不限制实际像元为 3 arc-second。需显式产品声明及实际分辨率核查；不能默认 CGIAR v4.x = NASA SRTMGL3。API 也须留实际分辨率和版本，不能仅凭文件名认定真30m。
6. **空格与预算。** 内核对无 hits 格保留 -999，CLI 仍可成功；`rejected_missing` 在当前拒绝 NoData 路径下为零。结果必须明确未覆盖格数并阻断 P3-ready 状态；不得填零。`check_spec` 虽验单边上限和乘法溢出，仍缺实际内存预算；大图需资源边界，不能在本 Issue 顺带重写统计算法。
7. **参考生成器不能照搬。** `native_cpp/reference/capture_p1_p2.py:39–59` 读取固定 crop，使用中心减2.5 km 并生成10位原点；且依赖当前不存在的 vendor template。`engine/preprocess/terrel/auto_select_srtm_to_terrel.py:230–243` 通用数值 formatter 也会丢 `.000`。新的独立 comparator runner 必须从相同 `grid.cmn` 传递三位数值/字符串，不重跑旧脚本当新案例证据。
