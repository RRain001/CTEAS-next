## 明确结论

1. **SRTMGL1 海洋高程主要为 0 m：是。** GSHHG 独立判定的海洋有效像元 259,335 个，其中 258,549 个为零，占 **99.696917%**。
2. **SRTMGL3 海洋高程主要为 0 m：是。** 海洋有效像元 28,813 个，其中 28,690 个为零，占 **99.573109%**。
3. **两份数据在本域海洋区域存在实际 NoData：否。** 海洋实际 NoData 都是 0 个（0%）；两份完整 N35E129 瓦片实际 NoData 和掩膜无效数也都是 0。`NoData=-32768` 是元数据中的标识值，不表示文件包含该值。
4. **当前 P1 能否不经修改处理本域：可以，经现有动态 C++ `cteas_p1_terrain_case` 接口实际验证。** 两份完整原始 TIFF 各生成 40,000 格、0 空格、0 NoData 样本；独立统计与原生逐格计数完全相同。没有修改准入规则、P1/P2 科学代码或将 NoData 填成零。此结论限于本次输入和动态 CLI；未运行完整 #42 case/source-manifest 编排、G5 GUI 或 Wolsong 原版 Fortran TERREL。
5. **存在需要进一步调查的近岸异常：是。** GL1/GL3 的非零海洋像元分别为 786/123 个；其中距 GSHHG 岸线超过 150 m 的仍有 98/13 个，最远约 436.387 m。不能据此直接认定 DEM 错误，也不能强制清零。

## GSHHG 独立海陆分类与统计口径

来源沿用 [Issue #119](https://github.com/RRain001/CTEAS-next/issues/119) 的 [真实海岸线手动验收](https://github.com/RRain001/CTEAS-next/actions/runs/39229707308)，使用现有 `gshhg_v237_cache.py` 从项目 Release 恢复官方原字节并校验 ZIP、SHP 和四个 sidecar。

- GSHHG v2.3.7 Full L1 ZIP SHA256：`8dbbe7e071e77e9e75f2d639239099ebca8d5c16d6a07df8169729d49f15cf41`。
- `GSHHS_f_L1.shp` SHA256：`121435427911ea80624802e0f352d777eaf6ba6966ca5f07e687650e95329fd9`。
- 投影、Union、裁剪后的陆地：**199236048.296361 m²**；海洋：**200763951.703639 m²**；合计400,000,000 m²。与 #119 的记录仅有末位浮点差异。本地 Fiona 几何筛选得到1个多边形；#119 的 OGR bbox 初筛3个、实际相交1个，最终有效相交和 Union 面积一致。

原始像元统计定义：以原始 GeoTIFF 的 double 精度像元中心投影到 UTM52N，选取 `533215 ≤ x < 553215`、`3942629 ≤ y < 3962629` 的中心。中心由 GSHHG 陆地 polygon 覆盖即为陆地，否则为海洋；**不读取高程来决定海陆**。原始像元总数 GL1=516,728、GL3=57,412。这里是中心点统计，不是像元足迹全相交面积统计；岸线混合像元和域边界足迹不能由本表推断为完全属于海或陆。

岸距为 UTM 平面内到原始 GSHHG polygon 真边界的最短距离；不把研究域裁剪边界当海岸。≤150 m 为近岸，>150 m 为远岸。为提速，索引模型框外30 km内的真实边界线段：域内已有真实海岸交叉，域内任一点距该岸线不超过域对角线28.3 km，故被排除线段不可能更近。每份数据另抽查14个异常点，对未裁剪完整原边界直接求距，差异均0 m。

L1 用作陆地外缘定义；此处不加入湖泊层或水深信息。该版本海岸线没有被当作同日实测岸线或30 m定位精度保证。零高程可能出现在陆地；非零高程也不能直接推翻 GSHHG 海洋分类。

## 200×200 计算网格：独立复算与原生 P1
